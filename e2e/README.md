# تست سر-تا-سر (E2E) — ربات مرورگر

این پوشه یک تست خودکار است که مثل کاربر واقعی با برنامه کار می‌کند: وارد
می‌شود، کالا و مشتری ثبت می‌کند، با «گوشی شبیه‌سازی‌شده» بارکد اسکن می‌کند
و بررسی می‌کند پاسخ‌های برنامه درست باشند. همین تست در دور ۶۲ دو باگ
واقعی پیدا کرد که ۲۶۱ تست واحد ندیده بودند.

## چه چیزی را تست می‌کند (۳۳ چک)

1. ورود با admin/admin12345 (شامل شروع دورهٔ آزمایشی در دیتابیس تازه)
2. گارد تغییر اجباری گذرواژهٔ پیش‌فرض در نصب تازه (نمایش، تغییر و بازشدن قفل)
3. لیست سبک صندوق `/api/products/pos` — شکل پاسخ و فیلدها
4. ثبت سریع کالا با فقط نام+قیمت → کد خودکار `P-…`
5. «ذخیره و کالای بعدی» → فرم باز می‌ماند و پاک می‌شود؛ Enter هم همین‌طور
6. اسکن بارکد با گوشی شبیه‌سازی‌شده (جفت‌شدن با PIN از پل) → پرشدن فیلد بارکد فرم کالا
7. نمایش کد و بارکد در جدول کالاها
8. عکس کالا (۵ چک): پیش‌نمایش محلی canvas، آپلود با نسخه، بندانگشتی نسخه‌دار
   جدول، GET عمومی با کش immutable، بارگذاری lazy کاشی صندوق
9. کد خودکار مشتری `C-…`
10. گرید صندوق از لیست سبک پر می‌شود
11. اسکنِ خارج از صفحهٔ صندوق → فقط پیام، سبد بی‌سروصدا پر نمی‌شود
12. ساخت/ویرایش تأمین‌کننده با payload قدیمی (creditLimit/tier) بدون خطا
13. PWA (۳ چک): manifest، sw.js و ثبت سرویس‌ورکر
14. چرخهٔ فروش (۵ چک): افزودن به سبد با بارکد، ثبت فروش نقدی، کاهش موجودی،
    بستن صندوق با اختلاف صفر، ثبت فاکتور در فروش‌ها
15. **بخش شبکه در تنظیمات (۲ چک رگرسیون):** تب «شبکه» در مرورگر دیده می‌شود و
    حالت‌های تک‌کامپیوتر/مشتری موجودند؛ حالت «سرور شبکه» (مخصوص برنامهٔ
    دسکتاپ) در مرورگر پنهان است و راهنمای آن نمایش داده می‌شود
16. ممیزی انتشار: بدون خطای کنسول/کرش صفحه/پاسخ 5xx در کل اجرا

## اجرا

سه پنجره لازم است (نمونه برای لینوکس/macOS):

```bash
# ۱) سرور با دیتابیس تازه (هشدار: دادهٔ همان مسیر را می‌سازد — مسیر tmp بگذارید)
cd server
POS_DATA_DIR=/tmp/e2e-data npm run start:prod   # یا: node dist/main.js

# ۲) بیلد دسکتاپ سرو شده
cd desktop
npm run build && npx vite preview --host 127.0.0.1 --port 1420

# ۳) خود تست
cd ..   # ریشهٔ پروژه
node e2e/ui-test.mjs
```

خروجی: فهرست ✓/✗ و در پایان «N/33 سبز». اسکرین‌شاط لحظهٔ پایان در
`e2e/last-run.png` ذخیره می‌شود. کد خروج ۰ یعنی همه سبز (مناسب برای اسکریپت انتشار).

## پیش‌نیاز اختیاری

تست به `playwright` و مرورگر کرومیوم نیاز دارد. این‌ها **وابستگی پروژه
نیستند** و به package.json اضافه نمی‌شوند — فقط ابزار تست‌اند:

```bash
npm i -D playwright
npx playwright install chromium
```

## تنظیمات (متغیرهای محیطی — همه اختیاری)

| متغیر | پیش‌فرض | توضیح |
|---|---|---|
| `E2E_UI` | `http://127.0.0.1:1420` | نشانی UI دسکتاپ |
| `E2E_API` | `http://127.0.0.1:4317/api` | ریشهٔ API سرور |
| `E2E_BRIDGE` | `http://127.0.0.1:4319` | نشانی HTTP پل اسکن گوشی |
| `E2E_EXECUTABLE_PATH` | — | مسیر کرومیوم جایگزین اگر مرورگر پیش‌فرض در دسترس نیست |

## نکته‌ها

- تست **تکرارپذیر** است: بارکد/نام‌ها هر اجرا یکتا هستند و کدهای مورد
  انتظار (`P-…`/`C-…`) از وضعیت فعلی دیتابیس محاسبه می‌شوند — لازم نیست
  هر بار دیتابیس تازه بسازید، ولی برای نتیجهٔ تمیز پیشنهاد می‌شود.
- در پایان هر اجرا چند کالای تستی و یک مشتری/تأمین‌کنندهٔ تستی در
  دیتابیس می‌ماند — روی دیتابیس واقعی فروشگاه اجرا نکنید.
