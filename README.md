# روشن POS

برنامه فروشگاهی ویندوز برای یک کامپیوتر و یک صندوق. نسخه آغازین با Tauri 2، React و TypeScript در محیط دسکتاپ اجرا می‌شود؛ API داخلی NestJS است و اطلاعات با Prisma در SQLite محلی ذخیره می‌شوند. برای فروش روزانه، VPS، PostgreSQL، Docker یا اینترنت لازم نیست.

## راه‌اندازی برای توسعه

پیش‌نیازها: Windows 10/11، Node.js 22، npm و (برای بازکردن پنجره Tauri) Rust همراه با ابزارهای C++ ویندوز و WebView2.

```powershell
npm run setup:dependencies
npm run dev
```

فرمان `npm run dev` API محلی و پنجره دسکتاپ را اجرا می‌کند. اگر هنوز Rust نصب نیست، برای مشاهده رابط در مرورگر دو پنجره ترمینال باز کنید:

```powershell
npm run dev:api
```

```powershell
npm --workspace desktop run dev
```

سپس نشانی محلی `http://127.0.0.1:1420` را باز کنید. API فقط روی `127.0.0.1:4317` در دسترس است.

برای ساخت نسخه آماده نصب ویندوز:

```powershell
npm run tauri:build
```

این فرمان فایل‌های API و رابط را می‌سازد، Node.js همراه وابستگی‌های لازم را در منابع نصب‌کننده قرار می‌دهد و نصب‌کننده NSIS با پسوند `.exe` تولید می‌کند. بسته MSI فعلاً غیرفعال است، چون WiX با نام دری برنامه در code page پیش‌فرض 1252 خطا می‌دهد. Rust، Visual Studio Build Tools و WebView2 برای ساخت Tauri لازم‌اند. نصب‌کننده، نصب‌کنندهٔ آفلاین WebView2 را هم در خود دارد تا روی کامپیوترهای بدون اینترنت هم نصب کامل انجام شود؛ حجم فایل نصب به همین دلیل بزرگ‌تر است. بعد از نصب، خود برنامه به اینترنت وابسته نیست.

رفتار برنامهٔ نصب‌شده هنگام اجرا:

- پنجرهٔ برنامه بلافاصله باز می‌شود و تا آماده‌شدن API محلی، پیام «در حال آماده‌سازی» نشان می‌دهد.
- اجرای Node.js همراه در پس‌زمینه انجام می‌شود و پنجرهٔ کنسول سیاه نمایش داده نمی‌شود.
- اگر API محلی به هر دلیل اجرا نشود، برنامه بی‌صدا بسته نمی‌شود؛ یک پیام خطای واضح (به همراه انتهای فایل گزارش) نمایش داده می‌شود.
- برای رفع مشکل، فایل گزارش `%APPDATA%\DarPOSERP\api.log` را بررسی کنید.

## ورود نخست

در اولین اجرا، برنامه جداول دیتابیس و اطلاعات نمونه را می‌سازد: چند کالا و دسته‌بندی، یک صندوق آغازین، مشتری نمونه و کاربر مدیر. اطلاعات ورود اولیه:

- نام کاربری: `admin`
- گذرواژه: `admin12345`

پس از ورود، از بخش **تنظیمات** گذرواژه پیش‌فرض را تغییر دهید. برای صندوقدار حساب جداگانه بسازید.

## نگهداری اطلاعات

فایل اصلی SQLite و نسخه‌های پشتیبان در مسیر زیر نگهداری می‌شوند:

```text
%APPDATA%\DarPOSERP\
├── pos.db
└── backups\
```

در توسعه هم همین مسیر استفاده می‌شود. برای ساخت نسخه پشتیبان از بخش **تنظیمات ← ساخت نسخه پشتیبان** استفاده کنید؛ همچنین با بستن هر نوبت کاری، به‌طور خودکار یک نسخه پشتیبان (با پیشوند `auto-`) ساخته می‌شود و ۱۰ نسخهٔ آخر نگه داشته می‌شوند. دیتابیس در مسیر اطلاعات کاربر قرار دارد و با حذف یا به‌روزرسانی برنامه از بین نمی‌رود. گذرواژه‌ها با bcrypt هش می‌شوند و API فقط روی loopback گوش می‌دهد.

## امکانات این نسخه

- ثبت فروش با جست‌وجوی نام، کد کالا یا بارکد؛ اسکنرهای USB که مانند صفحه‌کلید تایپ می‌کنند قابل استفاده‌اند.
- پرداخت نقدی، موبایلی و نسیه؛ چاپ رسید از پنجره چاپ ویندوز.
- بررسی موجودی قبل از فروش و ثبت اتمیک فاکتور، پرداخت و خروج انبار.
- **برگشت کالا از فروش (کامل یا جزئی):** کالای برگشتی دوباره به انبار می‌آید، گردش «برگشت فروش» ثبت می‌شود و برای فاکتور نقدی، پول از صندوقِ باز خارج می‌شود. اگر همهٔ اقلام یک فاکتور برگشت داده شوند، مبلغ برگشتی برابر مبلغ نهایی فاکتور (با احتساب تخفیف) است.
- **خرید و ورود کالا:** ثبت رسید خرید از تأمین‌کننده با چند قلم؛ موجودی افزایش می‌یابد، گردش «خرید» ثبت می‌شود و قیمت خرید کالاها به‌روز می‌گردد.
- **حساب نسیهٔ مشتری:** مانده بدهی هر مشتری (فروش نسیه − برگشتی‌ها − پرداخت‌ها) و ثبت وصولی نسیه؛ وصولی در صندوقِ باز به‌صورت ورودی نقدی ثبت می‌شود.
- **گزارش فروش با فیلتر تاریخ:** فهرست فروش‌ها با بازهٔ از/تا، دکمه‌های «امروز» و «۷ روز اخیر» و جمع مبلغ بازه.
- مدیریت کالا، قیمت، دسته‌بندی، مشتری و تأمین‌کننده؛ کالاهای بایگانی‌شده قابل مشاهده و بازگردانی‌اند.
- تعدیل دستی موجودی با گردش و سابقه کالا.
- بازکردن و بستن صندوق، ورودی و خروجی نقدی و نمایش اختلاف شمارش؛ **با بستن هر نوبت کاری به‌طور خودکار نسخه پشتیبان ساخته می‌شود (۱۰ نسخهٔ آخر نگه داشته می‌شود).**
- نقش مدیر و صندوقدار، ورود محلی، بازکردن دوبارهٔ دسترسی کاربر بسته‌شده، بازنشانی گذرواژهٔ کاربران توسط مدیر، تنظیمات فروشگاه، خلاصه روزانه و نسخه پشتیبان دستی.
- نام فروشگاه و پیام پایین رسید از تنظیمات خوانده می‌شود و روی همهٔ رسیدها و هدر برنامه نمایش می‌یابد.
- رابط راست‌به‌چپ به زبان دری و قیمت‌گذاری به افغانی.

## نکات معماری

- React فقط از REST API محلی استفاده می‌کند؛ منطق فروش و موجودی در NestJS است.
- فروش، ردیف‌های فاکتور، تغییر موجودی، گردش انبار و گزارش رویداد در یک تراکنش SQLite ثبت می‌شوند. خریدها، برگشتی‌های فروش و وصولی نسیه هم اتمیک و همراه با گردش انبار/صندوق ثبت می‌شوند.
- کلید یکتای درخواست فروش از ثبت تکراری یک درخواست جلوگیری می‌کند.
- تغییرات اسکیما فقط افزایشی‌اند: جدول‌های تازه با `CREATE TABLE IF NOT EXISTS` ساخته می‌شوند و دیتابیس‌های موجود دست‌نخورده می‌مانند.
- NestJS روی `127.0.0.1` اجرا می‌شود؛ در نسخه نصب‌شده، برنامه Node.js و API داخلی را خودکار از منابع همراه اجرا می‌کند و با بستن پنجره متوقف می‌شود. پنجرهٔ اصلی بلافاصله باز می‌شود و API در یک رشتهٔ پس‌زمینه بالا می‌آید تا شروع کِشندهٔ اول (اسکن آنتی‌ویروس، دیسک کند) باعث بسته‌شدن یا قفل‌شدن برنامه نشود. خطاهای شروع API به‌جای خروج بی‌صدا در یک پیام خطا نمایش داده می‌شوند و در `%APPDATA%\DarPOSERP\api.log` ثبت می‌شوند. پروسهٔ Node با پرچم `CREATE_NO_WINDOW` اجرا می‌شود تا پنجرهٔ کنسول نمایان نشود و تا ۱۸۰ ثانیه فرصت شروع دارد.
- داده‌های نخستین بار به‌طور خودکار ایجاد می‌شوند؛ `npm run db:seed` هم برای افزودن داده‌های نمایشی در محیط توسعه موجود است.
- فعلاً برای یک دستگاه و یک صندوق طراحی شده است. همگام‌سازی چند دستگاه/شعبه و حسابداری دوبل در این برش پیاده‌سازی نشده‌اند.

## فرمان‌های کمکی

```powershell
npm run build       # ساخت API و رابط وب
npm test            # بررسی منطق اتمیک checkout
npm run db:push     # همگام‌سازی schema با دیتابیس محلی
npm run db:seed     # افزودن داده‌های نمایشی
```
