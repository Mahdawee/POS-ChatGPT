# روشن POS

برنامه فروشگاهی ویندوز برای یک کامپیوتر و یک صندوق. نسخه آغازین با Tauri 2، React و TypeScript در محیط دسکتاپ اجرا می‌شود؛ API داخلی NestJS است و اطلاعات با Prisma در SQLite محلی ذخیره می‌شوند. برای فروش روزانه، VPS، PostgreSQL، Docker یا اینترنت لازم نیست.

## راه‌اندازی برای توسعه

پیش‌نیازها: Windows 10/11، Node.js 22، npm و (برای بازکردن پنجره Tauri) Rust همراه با ابزارهای C++ ویندوز و WebView2.

```powershell
npm run setup:dependencies
npm run dev
```

فرمان `npm run dev` API محلی و پنجره دسکتاپ را اجرا می‌کند. اگر هنوز Rust نصب نیست، برای مشاهده رابط در مرورگر دو پنجره ترمینال باز کنید:

```powershell
npm run dev:api
```

```powershell
npm --workspace desktop run dev
```

سپس نشانی محلی `http://127.0.0.1:1420` را باز کنید. API فقط روی `127.0.0.1:4317` در دسترس است.

برای ساخت نسخه آماده نصب ویندوز:

```powershell
npm run tauri:build
```

این فرمان فایل‌های API و رابط را می‌سازد، Node.js همراه وابستگی‌های لازم را در منابع نصب‌کننده قرار می‌دهد و نصب‌کننده NSIS با پسوند `.exe` تولید می‌کند. بسته MSI فعلاً غیرفعال است، چون WiX با نام دری برنامه در code page پیش‌فرض 1252 خطا می‌دهد. Rust، Visual Studio Build Tools و WebView2 برای ساخت Tauri لازم‌اند. نصب‌کننده، نصب‌کنندهٔ آفلاین WebView2 را هم در خود دارد تا روی کامپیوترهای بدون اینترنت هم نصب کامل انجام شود؛ حجم فایل نصب به همین دلیل بزرگ‌تر است. بعد از نصب، خود برنامه به اینترنت وابسته نیست.

رفتار برنامهٔ نصب‌شده هنگام اجرا:

- پنجرهٔ برنامه بلافاصله باز می‌شود و تا آماده‌شدن API محلی، پیام «در حال آماده‌سازی» نشان می‌دهد.
- اجرای Node.js همراه در پس‌زمینه انجام می‌شود و پنجرهٔ کنسول سیاه نمایش داده نمی‌شود.
- اگر API محلی به هر دلیل اجرا نشود، برنامه بی‌صدا بسته نمی‌شود؛ یک پیام خطای واضح (به همراه انتهای فایل گزارش) نمایش داده می‌شود.
- برای رفع مشکل، فایل گزارش `%APPDATA%\DarPOSERP\api.log` را بررسی کنید. حجم این فایل خودکار محدود می‌شود (بیش از ۲ مگابایت فقط انتهای آن نگه داشته می‌شود).

## ورود نخست

در اولین اجرا، برنامه جداول دیتابیس و اطلاعات نمونه را می‌سازد: چند کالا و دسته‌بندی، یک صندوق آغازین، مشتری نمونه و کاربر مدیر. اطلاعات ورود اولیه:

- نام کاربری: `admin`
- گذرواژه: `admin12345`

پس از ورود، از بخش **تنظیمات** گذرواژه پیش‌فرض را تغییر دهید. برای صندوقدار حساب جداگانه بسازید.

## نگهداری اطلاعات

فایل اصلی SQLite و نسخه‌های پشتیبان در مسیر زیر نگهداری می‌شوند:

```text
%APPDATA%\DarPOSERP\
├── pos.db
└── backups\
```

در توسعه هم همین مسیر استفاده می‌شود. برای ساخت نسخه پشتیبان از بخش **تنظیمات ← ساخت نسخه پشتیبان** استفاده کنید؛ همچنین با بستن هر نوبت کاری، به‌طور خودکار یک نسخه پشتیبان (با پیشوند `auto-`) ساخته می‌شود و ۱۰ نسخهٔ آخر نگه داشته می‌شوند.

**بازیابی نسخه پشتیبان:** برنامه را ببندید، فایل دلخواه از پوشهٔ `backups` را کپی کنید و به‌جای `pos.db` قرار دهید (فایل قبلی را با نام دیگری نگه دارید)، سپس برنامه را باز کنید. دیتابیس در مسیر اطلاعات کاربر قرار دارد و با حذف یا به‌روزرسانی برنامه از بین نمی‌رود. گذرواژه‌ها با bcrypt هش می‌شوند و API فقط روی loopback گوش می‌دهد.

## امکانات این نسخه

- ثبت فروش با جست‌وجوی نام، کد کالا یا بارکد؛ اسکنرهای USB که مانند صفحه‌کلید تایپ می‌کنند قابل استفاده‌اند.
- پرداخت نقدی، موبایلی و نسیه؛ **چاپ رسید با چاپگر حرارتی یا معمولی** — چاپ از یک سند مستقل با عرض ۷۲ میلی‌متر انجام می‌شود (متناسب با کاغذ حرارتی ۸۰ میلی‌متری؛ روی چاپگر معمولی هم چاپ می‌شود و با انتخاب «Microsoft Print to PDF» در پنجرهٔ چاپ، خروجی PDF ساخته می‌شود).
- بررسی موجودی قبل از فروش و ثبت اتمیک فاکتور، پرداخت و خروج انبار.
- **برگشت کالا از فروش (کامل یا جزئی):** کالای برگشتی دوباره به انبار می‌آید، گردش «برگشت فروش» ثبت می‌شود و برای فاکتور نقدی، پول از صندوقِ باز خارج می‌شود. اگر همهٔ اقلام یک فاکتور برگشت داده شوند، مبلغ برگشتی برابر مبلغ نهایی فاکتور (با احتساب تخفیف) است.
- **خرید و ورود کالا:** ثبت رسید خرید از تأمین‌کننده با چند قلم؛ موجودی افزایش می‌یابد، گردش «خرید» ثبت می‌شود و قیمت خرید کالاها به‌روز می‌گردد.
- **حساب نسیهٔ مشتری:** مانده بدهی هر مشتری (فروش نسیه − برگشتی‌ها − پرداخت‌ها) و ثبت وصولی نسیه؛ وصولی در صندوقِ باز به‌صورت ورودی نقدی ثبت می‌شود.
- **گزارش سود (بخش «گزارش‌ها»):** سود ناخالص، حاشیهٔ سود، بهای کالای فروخته‌شده، سود روزانه و پرفروش‌ترین کالاها در هر بازهٔ زمانی — با دکمهٔ **چاپ گزارش**. بهای خرید هر قلم هنگام فروش در فاکتور ذخیره می‌شود تا سود تاریخی دقیق باشد.
- **گزارش بدهی‌داران:** فهرست مشتریان بدهکار (نسیه) و بدهی به تأمین‌کنندگان، مرتب بر اساس مانده، با جمع کل و دکمهٔ چاپ.
- **خرید نسیه از تأمین‌کننده:** هنگام ثبت خرید می‌توانید مبلغ پرداخت‌شده را وارد کنید؛ مانده به‌عنوان بدهی در حساب تأمین‌کننده ثبت می‌شود و بعداً قابل تسویه است (ستون «بدهی» در فهرست تأمین‌کنندگان).
- **گزارش فروش با فیلتر تاریخ:** فهرست فروش‌ها با بازهٔ از/تا، دکمه‌های «امروز» و «۷ روز اخیر»، جمع مبلغ بازه و **خروجی CSV** برای اکسل.
- **ستون بدهی نسیه در فهرست مشتریان** و نمای کلی غنی‌تر در داشبورد: فروش/برگشتی/خرید امروز، بدهی نسیهٔ کل و ارزش انبار.
- مدیریت کالا، قیمت، دسته‌بندی، مشتری و تأمین‌کننده؛ کالاهای بایگانی‌شده قابل مشاهده و بازگردانی‌اند.
- تعدیل دستی موجودی با گردش و سابقه کالا.
- بازکردن و بستن صندوق، ورودی و خروجی نقدی و نمایش اختلاف شمارش؛ **با بستن هر نوبت کاری به‌طور خودکار نسخه پشتیبان ساخته می‌شود (۱۰ نسخهٔ آخر نگه داشته می‌شود).**
- نقش مدیر و صندوقدار، ورود محلی، بازکردن دوبارهٔ دسترسی کاربر بسته‌شده، بازنشانی گذرواژهٔ کاربران توسط مدیر، تنظیمات فروشگاه، خلاصه روزانه و نسخه پشتیبان دستی.
- نام فروشگاه و پیام پایین رسید از تنظیمات خوانده می‌شود و روی همهٔ رسیدها و هدر برنامه نمایش می‌یابد.
- **دخل و خرج فروشگاه:** ثبت هزینه‌های جاری (کرایه، برق، ترابری…) با دسته‌بندی؛ هزینهٔ پرداخت‌شده از صندوق، به‌صورت خروج نقدی در نوبتِ باز ثبت می‌شود و در گزارش Z و مبلغ مورد انتظار دیده می‌شود. گزارش سود، **سود خالص** (سود ناخالص − هزینه‌ها) را هم نشان می‌دهد.
- **برگشت خرید به تأمین‌کننده:** از جزئیات هر رسید خرید، کالای برگشتی را ثبت کنید؛ موجودی کم می‌شود، گردش «برگشت خرید» ثبت می‌شود و مبلغ در حساب تأمین‌کننده تسویه می‌گردد (نقد صندوق تغییر نمی‌کند). رسید چاپی برگشت خرید هم دارد.
- **قیمت عمده و خرده:** برای هر کالا قیمت عمده و حداقل تعداد عمده تعیین کنید؛ در صندوق فروش، وقتی تعداد خط به حد نصاب برسد قیمت خودکار عمده می‌شود و روی فاکتور «قیمت عمده» درج می‌گردد.
- **فاکتور معلق و میان‌برهای صفحه‌کلید:** با کلید F4 فاکتور جاری معلق می‌شود (تا ۲۰ فاکتور) و بعداً از دکمهٔ «معلق‌ها» ادامه می‌یابد؛ F1 جست‌وجوی کالا، F6 مبلغ دریافتی، F9 چاپ دوبارهٔ آخرین رسید (F2 همان صندوق فروش است).
- **پشتیبانی ترازوی بارکدی:** بارکدهای وزنی ۱۳ رقمیِ ترازو (پیشوند ۲ + کد ۵ رقمی PLU + وزن به گرم) هنگام اسکن، کالا را با مقدار وزنی به فاکتور اضافه می‌کنند؛ کد PLU را در «کد کالا» ثبت کنید.
- **خروجی PDF گزارش‌ها:** دکمهٔ «خروجی PDF» در گزارش‌ها، پنجرهٔ چاپ را با نام فایل مناسب باز می‌کند؛ چاپگر «Microsoft Print to PDF» را انتخاب کنید تا فایل PDF ساخته شود.
- **چاپ سند بدهی مشتری:** از حساب هر مشتری، سند بدهی (مانده، فروش‌های نسیهٔ اخیر و وصولی‌ها) با پیام یادآور چاپ می‌شود — برای بایگانی یا دادن به مشتری.
- **سه زبان: دری، پشتو و انگلیسی** — از سوئیچ پایین نوار کناری عوض می‌شود؛ جهت صفحه (راست‌به‌چپ/چپ‌به‌راست)، ترازبندی جداول و فرم‌ها، تاریخ و اعداد به‌صورت خودکار با زبان هماهنگ می‌شوند و انتخاب زبان ذخیره می‌شود. زبان روی رسیدها و گزارش‌های چاپی هم اعمال می‌شود.
- **کالای وزنی (کیلوگرمی):** برای هر کالا می‌توانید نوع «وزنی» را انتخاب کنید؛ مقدار در فاکتور تا ۳ رقم اعشار (مثلاً ۱٫۲۵ کیلو) وارد می‌شود، موجودی اعشاری نگهداری می‌شود و مجموع هر قلم به افغانیِ کامل گرد می‌شود تا حساب نقد سر راست بماند.
- **مدیریت انقضای کالا:** تاریخ انقضای اختیاری برای هر کالا؛ کالاهای منقضی یا نزدیک انقضا (۱۴ روز) در داشبورد و فهرست کالاها با برچسب هشدار نمایش داده می‌شوند.
- **ورود گروهی کالا از فایل CSV/اکسل:** الگوی نمونه را دانلود کنید، پر کنید و در بخش کالاها «ورود از فایل» را بزنید؛ تطابق بر اساس بارکد، کد کالا و سپس نام انجام می‌شود (کالای موجود به‌روز می‌شود، تازه ساخته می‌شود).
- **چاپ لیبل قیمت با بارکد:** برای هر کالا، برگهٔ A4 از لیبل‌های ۵۰×۲۵ با نام، بارکد CODE128 و قیمت.
- **گزارش پایان نوبت (Z):** با بستن صندوق، خلاصهٔ کامل نوبت (فروش نقدی/موبایلی/نسیه، برگشتی‌ها، ورودی/خروجی دستی، مبلغ مورد انتظار، شمارش و اختلاف) نمایش داده و روی چاپگر حرارتی قابل چاپ است.
- **لوگوی رسید:** در تنظیمات یک تصویر کوچک انتخاب کنید تا بالای همهٔ رسیدها چاپ شود.
- **سفارش خرید پیشنهادی:** در بخش خریدها، دکمهٔ «پیشنهاد سفارش» کالاهای زیر حداقل موجودی را با مقدار پیشنهادی فهرست می‌کند و رسید خرید را به‌صورت خودکار پر می‌کند.
- **حالت شبکهٔ محلی (چند کامپیوتر):** در تنظیمات، دستگاه اصلی را «سرور شبکه» کنید (API روی 0.0.0.0 گوش می‌دهد؛ در ویندوز اجازهٔ فایروال بدهید) و دستگاه‌های دیگر را «مشتری شبکه» با نشانی سرور (مثلاً `http://192.168.1.10:4317`). داده‌ها روی دستگاه سرور نگهداری می‌شوند. راهنمای کامل گام‌به‌گام در [docs/network-guide.md](docs/network-guide.md) است.
- **بررسی به‌روزرسانی:** در تنظیمات، دکمهٔ «بررسی به‌روزرسانی» نسخهٔ نصب‌شده را با آخرین نسخهٔ گیت‌هاب مقایسه می‌کند و صفحهٔ دانلود را باز می‌کند.
- **تنظیمات تب‌دار و تنظیمات چاپ:** صفحهٔ تنظیمات به تب‌های فروشگاه، «رسید و چاپ»، بارکدخوان، شبکه و سیستم سازمان یافته است. می‌توانید تعداد نسخه‌های چاپ رسید (۱ تا ۳)، چاپ خودکار رسید پس از ثبت فروش و چاپ/حذف لوگو روی رسید را تعیین کنید.
- **اتصال بارکدخوان و اسکنر QR:** در تب «بارکدخوان / QR» آزمون زندهٔ اتصال با نمایش مقدار خوانده‌شده، نوع کد (EAN-13، UPC-A، EAN-8، ترازوی وزنی، QR، CODE128)، سرعت خواندن (نویسه بر ثانیه) و کلید پایان اسکن (Enter/Tab) انجام می‌شود؛ وضعیت آخرین آزمون ذخیره می‌ماند، صدای بوق پس از اسکن موفق در صندوق فروش پخش می‌شود و دستگاه‌های رایج افغانستان (Honeywell Voyager، Zebra DS2208/DS2278، Sunlux/X-9/Y-990، Netum، Tera — همه به‌صورت صفحه‌کلید USB بدون درایور) فهرست شده‌اند.
- **رفع خطاهای «Internal server error»:** خطاهای دیتابیس (رکورد حذف‌شده، مقدار تکراری مانند بارکد، وابستگی رکورد و…) به‌جای خطای ۵۰۰ با پیام روشن دری نمایش داده می‌شوند و جزئیات کامل در فایل api.log ثبت می‌گردد؛ خطاهای ناشناخته هم پیام دری با ارجاع به لاگ می‌دهند.
- **تشخیص قطعی خطاها (نسخهٔ ۰.۸):** پیام‌های ۵۰۰ یک «کد مرجع» کوتاه (مثل E4172) نشان می‌دهند که همان کد در api.log هم ثبت می‌شود تا خطاها تلفنی قابل پیگیری باشند؛ خطاهای پرایسما حتی وقتی instanceof به‌خاطر باندل شدن شکست بخورد هم تشخیص داده می‌شوند (duck-typing) و خطای «سرور مشغول است» (P2028) پیام تلاش مجدد می‌گیرد.
- **چاپ دو-حالته:** در تنظیمات → رسید و چاپ، بین «با پنجرهٔ چاپ» (کامل: لوگو، فونت و QR) و «چاپ سریع بدون پنجره» (متن سادهٔ رسید که مستقیم به چاپگر می‌رود، بدون هیچ پنجره‌ای) انتخاب کنید؛ نام چاپگر مشخص را وارد کنید، با «آزمون چاپ سریع» تست بگیرید و اگر چاپ سریع ممکن نشد برنامه خودکار به پنجرهٔ چاپ برمی‌گردد.
- **QR پرداخت روی رسید:** متن یا لینک پرداخت (HesabPay، M-Paisa، شمارهٔ حساب…) را در تنظیمات وارد کنید تا یک QR روی رسید فروش و سند بدهی چاپ شود.
- **بکاپ قابل حمل و بازیابی:** خروجی فایل کامل دیتابیس در پوشهٔ Documents/DarPOS-Backups (برای فلش یا کامپیوتر دیگر) و «بازیابی از فایل بکاپ» با گرفتن خودکار نسخهٔ امن پیش از تغییر و بازگشت خودکار اگر فایل معتبر نباشد.
- **نمایشگر مشتری (صفحهٔ دوم):** پنجره‌ای جدا برای دیدن مشتری که جمع فاکتور زنده را بزرگ نشان می‌دهد (از تنظیمات → سیستم باز کنید).
- **فروش سریع‌تر:** کلیدهای Alt+۱ تا Alt+۹ کالای هم‌شمردهٔ شبکه را به فاکتور می‌افزایند (شماره روی کارت‌ها درج شده) و دکمهٔ «تکرار آخرین خرید» همهٔ اقلام آخرین فاکتور مشتری را یک‌جا اضافه می‌کند.
- **قفل سریع صفحه (Ctrl+L):** مثل ویندوز-L؛ صفحه با گذرواژه دوباره باز می‌شود بدون خروج از حساب.
- **راهنمای میان‌برها:** کلید «?» جدول همهٔ میان‌برها را نشان می‌دهد.
- **حالت تیره:** با دکمهٔ ماه/خورشید در نوار بالا؛ چاپ و رسیدها همیشه روشن چاپ می‌شوند.
- **نمودار فروش ۱۴ روز اخیر** در نمای کلی، **فروش بر اساس دسته‌بندی** و **ساعت‌های پرکار** در گزارش‌ها، **صفحهٔ لاگ فعالیت** برای مدیر (چه کسی چه کاری کِی)، **هشدار کم‌موجودی/انقضا هنگام ورود مدیر**، **صفحه‌بندی فهرست فروش‌ها** (۱۰۰تایی + «نمایش بیشتر»)، **جست‌وجوی سرور-ساید کالاها** در فهرست کالاها (برای انبارهای بزرگ) و **فاکتور رسمی A4** با جای امضا برای عمده‌فروشی.
- **بارگذاری تأخیری صفحات:** باندل اولیه حدود ۴۰٪ سبک‌تر شد و صفحات کم‌کار فقط هنگام باز شدن بارگیری می‌شوند.
- **نشست لغزان و پایداری بیشتر:** توکن ورود هر ۴ ساعت در پس‌زمینه تازه می‌شود تا صندوقدار وسط کار بیرون نیفتد؛ خطاهای رابط به‌جای صفحهٔ سفید در یک کارت با دکمهٔ «بارگذاری دوباره» نمایش داده می‌شوند.
- دیتابیس SQLite در حالت WAL اجرا می‌شود (خواندن گزارش‌ها هنگام ثبت فروش متوقف نمی‌شود) و آمار پرس‌وجو روزانه تازه می‌شود.

## نکات معماری

- React فقط از REST API محلی استفاده می‌کند؛ منطق فروش و موجودی در NestJS است.
- فروش، ردیف‌های فاکتور، تغییر موجودی، گردش انبار و گزارش رویداد در یک تراکنش SQLite ثبت می‌شوند. خریدها، برگشتی‌های فروش و وصولی نسیه هم اتمیک و همراه با گردش انبار/صندوق ثبت می‌شوند.
- کلید یکتای درخواست فروش از ثبت تکراری یک درخواست جلوگیری می‌کند.
- تغییرات اسکیما فقط افزایشی‌اند: جدول‌های تازه با `CREATE TABLE IF NOT EXISTS` ساخته می‌شوند و ستون‌های افزوده‌شده به جداول موجود، هنگام راه‌اندازی با `ALTER TABLE ... ADD COLUMN` (به‌صورت idempotent) به دیتابیس‌های نصب‌شده اضافه می‌شوند؛ داده‌های قبلی دست‌نخورده می‌مانند.
- پرداخت به تأمین‌کننده فقط در حساب او ثبت می‌شود و نقد صندوق را تغییر نمی‌دهد (برخلاف وصولی نسیهٔ مشتری که در صندوقِ باز به‌صورت ورودی نقدی ثبت می‌شود).
- NestJS به‌طور پیش‌فرض روی `127.0.0.1` اجرا می‌شود؛ در حالت «سرور شبکه» روی `0.0.0.0` بالا می‌آید و در حالت «مشتری شبکه» API محلی اصلاً اجرا نمی‌شود (حالت در فایل `%APPDATA%\\DarPOSERP\\network-mode` ذخیره می‌شود). در نسخه نصب‌شده، برنامه Node.js و API داخلی را خودکار از منابع همراه اجرا می‌کند و با بستن پنجره متوقف می‌شود. پنجرهٔ اصلی بلافاصله باز می‌شود و API در یک رشتهٔ پس‌زمینه بالا می‌آید تا شروع کِشندهٔ اول (اسکن آنتی‌ویروس، دیسک کند) باعث بسته‌شدن یا قفل‌شدن برنامه نشود. خطاهای شروع API به‌جای خروج بی‌صدا در یک پیام خطا نمایش داده می‌شوند و در `%APPDATA%\DarPOSERP\api.log` ثبت می‌شوند. پروسهٔ Node با پرچم `CREATE_NO_WINDOW` اجرا می‌شود تا پنجرهٔ کنسول نمایان نشود و تا ۱۸۰ ثانیه فرصت شروع دارد.
- داده‌های نخستین بار به‌طور خودکار ایجاد می‌شوند؛ `npm run db:seed` هم برای افزودن داده‌های نمایشی در محیط توسعه موجود است.
- حالت شبکهٔ محلی برای چند صندوق در یک فروشگاه طراحی شده است (یک سرور، چند مشتری)؛ همگام‌سازی چند شعبه از طریق اینترنت و حسابداری دوبل پیاده‌سازی نشده‌اند.
