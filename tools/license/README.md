# ابزار لایسنس «روشن» (Dar POS)

برنامه پولی است و با لایسنس فعال می‌شود. این پوشه ابزار فروشنده (شما) برای
صادر کردن لایسنس برای دکان‌دارهاست — بدون نیاز به اینترنت در دکان.

## پنل گرافیکی (راه راحت)

به‌جای خط فرمان، **پنل مدیریت لایسنس** را باز کنید — یک صفحهٔ فارسی که کل
کار را با موس انجام می‌دهد:

- روی ویندوز: دابل‌کلیک روی **`panel-run.bat`** (فقط Node.js نصب باشد).
- یا در خط فرمان: `node tools/license/panel.js`

پنل خودش در مرورگر باز می‌شود (`http://127.0.0.1:4390`) و شامل:

| سربرگ | کار |
| --- | --- |
| صدور لایسنس | فرم نام مشتری + کلید دستگاه + پلن (ماهانه/سالانه/دلخواه/ابدی) → متن لایسنس آمادهٔ کپی |
| دفتر لایسنس‌ها | سابقهٔ همهٔ لایسنس‌ها با جستجو، وضعیت (فعال/منقضی/لغوشده)، کپی دوباره، تمدید، لغو و خروجی CSV/JSON |
| بررسی لایسنس | Paste متن لایسنس → بررسی امضا و محتوا (قبل از فرستادن برای مشتری) |
| کلیدها و راهنما | وضعیت کلیدها، ساخت جفت‌کلید، هشدار ناهماهنگی با کلید داخل برنامه، راهنمای فروش |

دفتر در `ledger.json` کنار همین فایل ذخیره می‌شود (در `.gitignore` است) —
گاهی از آن خروجی JSON بگیرید. پنل فقط روی همین دستگاه گوش می‌دهد و کلید
خصوصی هرگز به مرورگر فرستاده نمی‌شود.

## جریان کار (برای هر فروش)

1. مشتری برنامه را نصب می‌کند و باز می‌کند. صفحهٔ لایسنس **کلید دستگاه**
   (Machine Key) را نشان می‌دهد، به شکل `MK-XXXX-XXXX-XXXX-XXXX`.
   مشتری این کلید را برای شما می‌فرستد (پیام/وایل/تلفن).
2. شما لایسنس صادر می‌کنید:

   ```bash
   node tools/license/cli.js issue \
     --customer "دکان احمد" \
     --plan YEARLY \
     --machine-key MK-1234-ABCD-5678-EF90
   ```

3. بلوک لایسنس چاپ‌شده را برای مشتری می‌فرستید؛ او آن را در صفحهٔ لایسنس
   برنامه Paste و فعال می‌کند.

## پلن‌ها

| پلن | اعتبار |
| --- | --- |
| `MONTHLY` | ۳۰ روز (پیش‌فرض؛ با `--days` تغییر می‌کند) |
| `YEARLY` | ۳۶۵ روز (با `--days` تغییر می‌کند) |
| `CUSTOM` | هر مدتی که با `--days N` یا `--expires YYYY-MM-DD` بدهید |
| `LIFETIME` | ابدی |

نمونه با تاریخ دلخواه:

```bash
node tools/license/cli.js issue --customer "دکان احمد" --plan CUSTOM \
  --machine-key MK-... --expires 2027-03-21 --note "پرداخت نقدی"
```

## کلیدها

- `keygen` فقط **یک بار** و فقط روی دستگاه خودتان:
  `node tools/license/cli.js keygen`
- `keys/private.pem` ⚠️ **هرگز جایی آپلود/کامیت نکنید** (در `.gitignore`
  است). از آن چند بکاپ امن (مثلاً فلش جدا + گذرواژه) نگه دارید —
  **بدون کلید خصوصی نمی‌توانید لایسنس جدید صادر کنید** و از دست دادنش
  یعنی صادر کردن کلید تازه و بی‌اعتبار شدن همهٔ لایسنس‌های قبلی.
- `keys/public.pem` عمومی است و نسخهٔ داخل آن در
  `server/src/license/license-public-key.ts` embed شده و با برنامه توزیع
  می‌شود.

### خطای `DECODER routines :: unsupported` هنگام صدور

یعنی فایل `private.pem` وجود دارد اما محتوایش کلید خصوصی معتبر نیست —
خالی، ناقص کپی‌شده، یا کلید/متن اشتباه ذخیره شده. چنین کلیدی هرگز
لایسنسی را امضا نکرده، پس جایگزین‌کردنش بی‌ضرر است:

1. در پنل، سربرگ «کلیدها و راهنما» → دکمهٔ **«بازسازی جفت‌کلید»** را
   بزنید (وقتی کلید خراب باشد تأیید «مطمئنم» لازم نیست؛ در خط فرمان
   `node tools/license/cli.js keygen` هم کلید خراب را بدون `--force`
   جایگزین می‌کند).
2. همان‌جا **«همگام‌سازی کلید عمومی با سورس برنامه»** را بزنید و برنامه
   را با `npm run tauri:build` دوباره بسازید — تا کلید عمومی تازه داخل
   برنامه embed شود.
3. از این به بعد لایسنس‌های صادرشده روی نسخهٔ تازهٔ برنامه فعال می‌شوند.

(اگر فقط کلید را با Notepad باز/ذخیره کرده‌اید و «UTF-8 with BOM» شده،
پنل خودش BOM را نادیده می‌گیرد و کاری لازم نیست.)

## دستورهای کمکی (خط فرمان — معادل پنل)

```bash
node tools/license/cli.js machinekey                 # کلید دستگاه فعلی
node tools/license/cli.js show --file license.txt    # محتوای یک لایسنس
node tools/license/cli.js verify --file license.txt --machine-key MK-...
```

متغیرهای محیطی پنل (اختیاری): `LM_PORT` (پورت، پیش‌فرض ۴۳۹۰)، `LM_KEYS_DIR`
(پوشهٔ کلیدها)، `LM_LEDGER_PATH` (مسیر دفتر)، `LM_NO_OPEN=1` (مرورگر خودکار باز
نشود).

## امنیت — چه چیزهایی محافظت می‌شود

- **امضا (Ed25519):** هر تغییری در متن لایسنس (تاریخ، پلن، دستگاه) امضا
  را می‌شکند.
- **قیل به دستگاه:** لایسنس فقط روی همان دستگاهی کار می‌کند که کلیدش
  برایش صادر شده؛ کپی به کامپیوتر دیگر = «این لایسنس برای دستگاه دیگری
  صادر شده».
- **ضد دستکاری تاریخ:** برنامه بزرگ‌ترین تاریخی که تا حالا دیده را هم
  در دیتابیس و هم در یک فایل سایهٔ امضاشده (خارج از بکاپ‌ها) نگه
  می‌دارد. برگرداندن ساعت، مدت را بلند نمی‌کند و برگرداندن بیش از ۲۴
  ساعت، برنامه را قفل می‌کند تا لایسنس معتبر فعال شود.
- **دورهٔ آزمایشی:** ۱۴ روز از اولین اجرا، بعد از آن لایسنس لازم است.
- **سازگاری با آینده:** لایسنس‌ها با `features: ["*"]` صادر می‌شوند، پس
  فیتچرهای نسخه‌های بعدی هم زیر همین لایسنس کار می‌کنند؛ ساختار
  payload نسخه‌بندی شده است (`v: 1`).

برای برنامهٔ آفلاین، «غیرقابل‌شکستن مطلق» وجود ندارد (کسی که کد را
دستکاری کند هر چیزی را می‌شکند) — این طرح موانع چندلایه است: امضا +
قیل به دستگاه + ساعت یک‌طرفه + دو نقطهٔ اعمال (middleware سرور و خود
فرایند فروش).
