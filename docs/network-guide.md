# راهنمای شبکهٔ محلی (چند کامپیوتر در یک فروشگاه)

برنامهٔ روشن به‌صورت پیش‌فرض روی **یک کامپیوتر** کار می‌کند: دیتابیس، API و رابط همه روی همان دستگاه‌اند و هیچ شبکه‌ای لازم نیست. اگر چند صندوق در یک فروشگاه دارید، می‌توانید بدون اینترنت و فقط با یک **کابل یا وای‌فای محلی**، چند کامپیوتر را به یک دیتابیس مشترک وصل کنید.

- همهٔ کامپیوترها باید در **یک شبکهٔ محلی** باشند (به یک مودم/سوئیچ وصل).
- **دیتابیس و لایسنس فقط روی دستگاه سرور** نگهداری می‌شوند؛ کامپیوترهای مشتری فقط به سرور وصل می‌شوند.
- اگر دستگاه سرور خاموش باشد، کامپیوترهای مشتری نمی‌توانند فروش ثبت کنند؛ فروش‌های آن‌ها در «صف آفلاین» می‌مانند و به‌محض وصل‌شدن سرور، خودکار ارسال می‌شوند. خروج از حالت مشتری همیشه ممکن است — حتی وقتی سرور در دسترس نیست.

## ۱. آماده‌سازی دستگاه سرور

1. برنامه را روی دستگاهی که میزبان دیتابیس است نصب و اجرا کنید و از حساب مدیر وارد شوید.
2. به **تنظیمات ← شبکه** بروید.
3. گزینهٔ **«این دستگاه سرور باشد (سرور شبکه)»** را انتخاب کنید و ذخیره کنید.
4. برنامه را **کاملاً ببندید و دوباره باز کنید** (API باید با نشانی `0.0.0.0` بالا بیاید).
5. در همان صفحهٔ شبکه، نشانی‌های سبزرنگ (مثلاً `http://192.168.1.10:4317`) برای شما فهرست می‌شوند — یکی را بردارید و در دستگاه‌های مشتری وارد کنید. با دکمهٔ **«آزمایش اتصال»** می‌توانید درستی نشانی را بسنجید.

### اجازهٔ فایروال ویندوز

بار اول که برنامه در حالت سرور اجرا می‌شود، ویندوز ممکن است پنجرهٔ «Windows Security Alert» نشان دهد — روی **Allow access** کلیک کنید. اگر پنجره نمایش داده نشد یا اشتباهی رد شد، اجازه را دستی اضافه کنید:

- **راه آسان (پیشنهادی):** ویندوز را ری‌استارت کنید و برنامه را در حالت سرور باز کنید تا پنجرهٔ اجازه دوباره ظاهر شود.
- **راه دستی:** Command Prompt را با گزینهٔ Run as administrator باز کنید و این فرمان را اجرا کنید:

```bat
netsh advfirewall firewall add rule name="Dar Pos Server" dir=in action=allow protocol=TCP localport=4317
```

برای حذف قانون در آینده:

```bat
netsh advfirewall firewall delete rule name="Dar Pos Server"
```

> نکته: فقط روی **دستگاه سرور** اجازهٔ فایروال لازم است؛ کامپیوترهای مشتری چیزی نصب نمی‌کنند و پورتی باز نمی‌کنند.

## ۲. راه‌اندازی دستگاه‌های مشتری

1. همان نصب‌کنندهٔ برنامه را روی کامپیوتر صندوق نصب کنید (فقط رابط کار می‌کند؛ API محلی آن اجرا نمی‌شود).
2. وارد شوید و به **تنظیمات ← شبکه** بروید.
3. گزینهٔ **«اتصال به سرور فروشگاه (مشتری شبکه)»** را انتخاب کنید.
4. نشانی سبزرنگی را که از صفحهٔ شبکهٔ دستگاه سرور برداشته‌اید (مثلاً `http://192.168.1.10:4317`) وارد کنید و ذخیره کنید.
5. با دکمهٔ **«آزمایش اتصال»** مطمئن شوید پیام «اتصال برقرار شد» می‌گیرید. برنامه خودش دوباره بارگذاری می‌شود و از این پس به سرور وصل است.

حساب‌های کاربری و لایسنس مالکیت دستگاه سرور‌اند؛ روی دستگاه مشتری با همان کاربران فروشگاه وارد شوید.

## ۳. نشانی IP ثابت برای دستگاه سرور (پیشنهادی)

اگر مودم شما نشانی دستگاه سرور را عوض کند، کامپیوترهای مشتری وصل نمی‌شوند و باید نشانی تازه را دوباره وارد کنید. برای جلوگیری از این کار، برای دستگاه سرور یک IP ثابت بگیرید:

1. ابتدا نشانی فعلی و دروازه را یادداشت کنید: در Command Prompt بنویسید `ipconfig` (خط IPv4 Address و Default Gateway).
2. در ویندوز: **Settings ← Network & internet ← Properties (کارت شبکه) ← IP assignment ← Edit ← Manual ← IPv4 را روشن کنید.**
3. یک نشانی آزاد با همان رنج بگذارید (مثلاً اگر مودم `192.168.1.1` است، `192.168.1.50`).
4. Subnet mask را `255.255.255.0`، Gateway را نشانی مودم (مثلاً `192.168.1.1`) بگذارید.
5. DNS را `192.168.1.1` یا `8.8.8.8` بگذارید و ذخیره کنید.

روش دیگر: در تنظیمات مودم، برای دستگاه سرور **DHCP Reservation** تعریف کنید تا همیشه همان نشانی را بگیرد.

## ۴. عیب‌یابی

| نشانه | علت رایج | راه‌حل |
|---|---|---|
| مشتری «اتصال ممکن نشد» می‌دهد | دستگاه سرور روشن نیست یا برنامه‌اش باز نیست | برنامهٔ سرور را باز کنید و مطمئن شوید در حالت سرور است |
| نشانی سرور در دسترس نیست | فایروال ویندوز جلوی پورت ۴۳۱۷ را گرفته | پنجرهٔ اجازه را تأیید کنید یا فرمان `netsh` بخش ۱ را اجرا کنید |
| مشتری وصل بود، حالا وصل نمی‌شود | نشانی IP سرور عوض شده | نشانی تازه را از صفحهٔ شبکهٔ سرور بردارید و در مشتری به‌روز کنید؛ یا IP ثابت بدهید (بخش ۳) |
| روی مشتری «سرور پاسخ داد اما سلامت آن تایید نشد» | برنامهٔ دیگری روی همان پورت ۴۳۱۷ است | روی دستگاه سرور برنامه‌های اضافی که پورت ۴۳۱۷ می‌گیرند را ببندید |
| سرور با پیام «نمونهٔ قدیمی تک‌کامپیوتری در پس‌زمینه فعال است» بالا نمی‌آید | یک پروسهٔ node.exe قدیمی از اجرای قبلی مانده | برنامه را کاملاً ببندید و در Task Manager هر پروسهٔ `node.exe` باقی‌مانده را پایان دهید یا ویندوز را ری‌استارت کنید |
| فروش روی مشتری ثبت نشد | سرور موقتاً در دسترس نبوده | فاکتور در «صف آفلاین» ذخیره شده است؛ با دکمهٔ «ارسال دوبارهٔ فاکتورهای ذخیره‌شدهٔ آفلاین» در تنظیمات شبکه ارسال شود (خودکار هم دوباره تلاش می‌شود) |

برای جزئیات فنی، فایل `%APPDATA%\DarPOSERP\api.log` روی دستگاه سرور را بررسی کنید.

## ۵. برگشت به حالت تک‌کامپیوتر

از حالت مشتری همیشه می‌توانید خارج شوید — حتی اگر سرور در دسترس نیست:

1. در دستگاه مشتری به **تنظیمات ← شبکه** بروید.
2. گزینهٔ **«هر دستگاه مستقل کار کند (تک‌کامپیوتر)»** را انتخاب و ذخیره کنید.
3. برنامه را **کاملاً ببندید و دوباره باز کنید**. از این پس API محلی و دیتابیس همان دستگاه استفاده می‌شود.

روی دستگاه سرور هم همین کار را انجام دهید تا API دیگر در شبکه در دسترس نباشد و برای پورت ۴۳۱۷ اجازهٔ فایروال لازم نباشد.

> **توجه:** فروش‌های ثبت‌شده در حالت مشتری، در دیتابیس سرور ذخیره شده‌اند. اگر دستگاه مشتری را به حالت تک‌کامپیوتر برگردانید، آن فروش‌ها در دیتابیس محلی آن دستگاه نیستند و فقط فروش‌های آفلاینِ هنوز ارسال‌نشده (در صف آفلاین) باقی می‌مانند.

## ۵. حالت توسعه (npm run dev)

در توسعه، سرور API با فرمان جداگانهٔ `npm run dev` بالا می‌آید (نه با پوستهٔ Tauri)، پس همان قاعدهٔ نسخهٔ نصبی روی فایل `network-mode` اعمال می‌شود:

- انتخاب «سرور شبکه» در تنظیمات، فایل `network-mode` را در پوشهٔ داده (`%APPDATA%\DarPOSERP` در ویندوز) می‌نویسد؛ سرور در بوت بعدی آن را می‌خواند و روی `0.0.0.0` گوش می‌دهد.
- **بعد از ذخیره، کل فرمان `npm run dev` را با Ctrl+C ببندید و دوباره اجرا کنید** (هم API و هم پنجرهٔ برنامه باید دوباره بالا بیایند). تب شبکه پس از بازگشت، حالت «سرور شبکه فعال است» را نشان می‌دهد.
- اجازهٔ فایروال ویندوز بار اول برای `node.exe` (نه فقط برنامه) پرسیده می‌شود — Allow access بزنید.
- برای دستگاه مشتری در حالت توسعه کافی است نشانی `http://<IP سرور>:4317` را در تنظیمات ← شبکهٔ همان دستگاه وارد کنید؛ برنامهٔ مشتری از همان لحظه به سرور وصل می‌شود (بدون ری‌استارت فرمان).
- برگشتن به حالت تک‌کامپیوتر: در تنظیمات ← شبکه «تک‌کامپیوتر» را ذخیره و `npm run dev` را دوباره اجرا کنید.
